# 网络综合诊断指南

## 1. 诊断流程图
```
上不了网？
   │
   ├─[1] 网卡有IP且UP？── 否 → 检查网线/WiFi/DHCP
   │        │
   │        ├─[2] 有默认网关？── 否 → 检查DHCP/静态配置
   │        │        │
   │        │        ├─[3] 网关能ping通？── 否 → 检查路由器/网线/防火墙
   │        │        │        │
   │        │        │        ├─[4] DNS能解析？── 否 → 检查DNS配置/路由器DNS
   │        │        │        │        │
   │        │        │        │        ├─[5] 外部能ping通？── 否 → 检查外网/防火墙/禁ping
   │        │        │        │        │        │
   │        │        │        │        │        ├─[6] HTTP能访问？── 否 → 检查代理/HTTP服务
```

## 2. 各诊断项详解

### 网卡状态
- `ip -br addr`：`UP` = 链路正常，`DOWN` = 禁用，`NO-CARRIER` = 没插线
- 无线网卡显示 `wlan0` 等，有 `192.168.x.x` 说明拿到 IP

### 默认网关
- `ip route` 中 `default via X.X.X.X` 即网关
- 家用网络通常是路由器 IP（如 192.168.1.1）

### 网关连通性
- ping 通 = 局域网正常
- ping 不通但能上网 = 网关禁 ICMP（少见）

### DNS 解析
- `getent hosts` 解析失败 → DNS 配置错误或服务器故障
- 常见 DNS：运营商 DNS、114.114.114.114、8.8.8.8、223.5.5.5

### 外部连通性
- ICMP ping 被很多服务器屏蔽（如 baidu.com），不代表断网
- 用 HTTP 访问验证更可靠

### 路由表
- 正常应有：default 路由 + 局域网直连路由 + 可能的多条静态路由

### MTU
- 以太网标准 1500，PPPoE 拨号 1492，VPN 隧道可能更低
- 过大导致分片丢包，过小浪费带宽

## 3. 快速诊断案例

### 案例1：完全上不了网
```
[1] 网卡: wlan0 UP 192.168.1.197 ✅
[2] 网关: 192.168.1.1 ✅
[3] ping网关: 通 ✅
[4] DNS解析 baidu.com: 失败 ❌ ← 问题在这里！
```
→ 检查 /etc/resolv.conf 或路由器DHCP的DNS配置

### 案例2：能上微信不能开网页
```
[4] DNS解析: 失败 ❌
[5] ping 8.8.8.8: 通 ✅（纯IP能通）
```
→ DNS 服务器挂了，微信用IP直连所以没事

### 案例3：延迟高丢包
```
[5] ping 8.8.8.8: 通但 30% 丢包
```
→ 用 traceroute 技能逐跳定位丢包点

## 4. 组合使用
| 场景 | 技能组合 |
|------|---------|
| 断网排查 | net-diagnose + dns-query |
| 高延迟排查 | traceroute + net-diagnose |
| 安全审计 | nmap + tcpdump |
| 服务不可达 | port_check + http_req |
