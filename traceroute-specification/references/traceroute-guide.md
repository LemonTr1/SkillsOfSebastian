# 路由追踪详细指南

## 1. 原理
traceroute 利用 IP 的 TTL（Time To Live）字段：
1. 发送 TTL=1 的数据包，第一个路由器收到后 TTL 减为 0，丢弃并回送 ICMP Time Exceeded 报文
2. 逐步增加 TTL（1,2,3...），每个中间路由器都会回复
3. 最终到达目标时回复 ICMP Echo Reply（ICMP 模式）或 TCP ACK（TCP 模式）

## 2. 三种模式对比
| 模式 | 参数 | 原理 | 适用场景 |
|------|------|------|---------|
| ICMP | `-I` | 发送 ICMP Echo | 默认，最直观，但部分节点屏蔽ICMP |
| UDP | `-U` | 发送 UDP 到高端口 | 经典模式，防火墙对UDP更宽松 |
| TCP | `-T` | 发送 TCP SYN 到 80 端口 | 穿透防火墙效果最好 |

## 3. 输出解读
```
 1  192.168.1.1       1.2 ms   1.5 ms   1.3 ms   ← 路由器（本地网关）
 2  10.10.10.1        3.1 ms   3.2 ms   3.0 ms   ← 运营商接入层
 3  61.144.x.x        5.5 ms   5.8 ms   5.6 ms   ← 城域网
 4  * * *                                      ← 该跳无响应（防火墙屏蔽/黑洞）
 5  202.97.x.x       30.2 ms  30.5 ms  29.8 ms   ← 骨干网
 ...
 9  8.8.8.8          52.1 ms  51.8 ms  52.3 ms   ← 目标
```

### 每行含义
- 每行 3 个时间 = 发送了 3 个探测包
- `*` = 该探测包无响应（可能被丢弃或防火墙屏蔽）
- `!H` = 主机不可达，`!N` = 网络不可达，`!X` = 管理禁止

## 4. 诊断技巧
1. **定位延迟源**：如果第 1 跳（本地）延迟就高，问题在本地网络；如果延迟在某跳突然飙升，问题在那一跳
2. **识别出口**：运营商骨干网 IP（如 202.97.x.x 电信、219.158.x.x 联通、202.96.x.x 移动）能看出流量走哪家
3. **`*` 不一定是问题**：很多核心路由器配置了限速，不响应 ICMP，但不影响数据转发
4. **对比测试**：对国内目标（baidu.com）和国际目标（google.com）分别 traceroute，判断跨境出口质量
5. **Linux 下 traceroute 默认用 UDP**，`-I` 才是 ICMP；Windows 的 tracert 默认 ICMP

## 5. 常见问题
| 现象 | 可能原因 |
|------|---------|
| 第1跳就是 `*` | 网关禁 ICMP，或本地防火墙拦截 |
| 某跳后全部 `*` | 该跳丢包严重/黑洞路由/被屏蔽 |
| 延迟忽高忽低 | 链路拥塞或负载均衡切换 |
| 无法穿透到目标 | 目标禁 ICMP/UDP，改用 TCP 模式 `-T` |
